# 渠道监控 V3 厂商分类与排序

## 配置入口

后台「渠道监控」→「V2 / V3 监控配置」→「厂商与分组排序」。

1. 使用厂商行右侧的上下箭头调整厂商分区的顺序。
2. 展开厂商的「分组顺序」，使用上下箭头调整厂商内部的卡片顺序。
3. 点击页面顶部「保存」。用户端在下次自动刷新或手动刷新后采用新顺序。

分组排序列表遵循下方「监控分组」的选择；空选择仍表示全部分组。
综合分组可以在多个厂商下配置顺序，实际只在有对应厂商监控数据时显示。
新分组或未指定顺序的分组排在已配置分组后面，按分组 ID 升序排列。
厂商开关仍控制是否纳入监控；关闭厂商不会清除其已保存的顺序。

## 展示及兼容

用户 V3 页面按厂商显示标题和分组数量，多分组厂商独占一段卡片网格，单分组厂商并排显示；窄屏自动改单列。卡片指标、时间范围、时间线、刷新频率和用户倍率沿用原实现。

旧厂商配置遗漏 Kimi、智谱 GLM、DeepSeek、MiniMax 和 OpenCode，查询又只接纳配置中启用的平台，导致这些平台的流量被排除。读取旧配置时现在补齐缺失项，默认启用；显式保存过的关闭状态及模型列表保留。V2/V3 共用汇总配置，这项修复也适用于 V2 的可见数据及汇总范围。

排序保存在既有 `channel_monitor_v2_config.platforms` JSONB：数组顺序为厂商顺序，`platforms[].group_order` 为可选的分组 ID 有序数组。无需新增表或迁移 SQL，已有乐观版本检查继续生效。

排序只影响展示，不授予分组权限。用户快照中的排序 ID 经过服务端可访问分组与监控分组范围交集过滤，页面只排列矩阵接口实际返回的行，不根据配置凭空创建卡片。不修改账号出口、网关转发、计费、监控指标计算或主动探测行为。
